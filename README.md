# 創業檢查 Startup Checkup

給創業者、獨立開發者與小型團隊的 Codex skill：根據你提供的資料，找出目前最值得處理的一個問題，設計下一步驗證。

**版本：1.0.0｜初始公開版（試用）｜預設台灣繁體中文**

適合用來討論「接下來該投入什麼」。它會區分事實、推測與資料缺口，不替事業打總分，也不預測成功率。模型行為的驗證範圍見[驗證紀錄](tests/VALIDATION.md)。

## 什麼時候用

| 你的狀況 | 可以幫你釐清 |
| --- | --- |
| 有想法，但不知道先做什麼 | 哪個假設值得先驗證、能用什麼現成方法測試 |
| 產品做完，卻沒有人用 | 是接觸不到人、用途不清楚、操作卡住，還是需求尚未成立 |
| 有人用，卻不願付費 | 使用者與付費者是否不同、價格與購買理由缺什麼證據 |
| 有訂單，交付卻越來越累 | 哪段流程最常等待、重工或依賴創辦人 |
| 想排功能優先順序 | 先查現有能力與實際缺口，再決定修正、驗證或暫緩 |

單純修 bug、調整版面、改文案，或拆解已核准功能的工程任務，不需要重做創業診斷。它也不提供投資標的建議、法律或會計意見。

## 你會拿到什麼

一次定向檢查通常包含：

1. **結論與限制**：這次查了什麼、沒查什麼，目前能判斷到哪裡。
2. **證據與假設**：哪些來自你提供的資料，哪些仍待確認。
3. **一個主要卡點**：可能原因、其他合理解釋，以及如何區分。
4. **一張驗證卡**：具體動作、觀察方式、投入上限及結果後的下一步。

例如，接單服務經常延遲，可能先需要分清「等創辦人校對」和「反覆修改」各花多少時間，再決定是否交接工作。看[完整合成範例](examples/service-delivery.md)，了解輸入與輸出的樣子。

## 安裝到 Codex

需要能使用本機 skills 的 Codex 環境，以及該環境所需的帳號與模型服務。本套件沒有自己的服務、追蹤碼或 API key；一般診斷不需要 Python。其他 agent 平台尚未驗證。

1. 從 [v1.0.0 下載頁](https://github.com/FarceurLiu/startup-checkup/releases/tag/v1.0.0)下載 `startup-checkup-1.0.0.zip` 並解壓縮。也可用 Git 取得原始碼。
2. 將包含 `SKILL.md` 的資料夾命名為 `startup-checkup`，保留其中的子資料夾。
3. 選一個安裝位置，放入完整資料夾：

| 範圍 | 安裝後的入口檔案 |
| --- | --- |
| 僅供某個專案使用 | `<專案根目錄>/.agents/skills/startup-checkup/SKILL.md` |
| 供個人各專案共用 | `<使用者家目錄>/.agents/skills/startup-checkup/SKILL.md` |

在 macOS／Linux，使用者家目錄可寫成 `~`。只需安裝一份；若已有同名資料夾，先備份並比對，不直接覆蓋。確認沒有多包一層 `startup-checkup/startup-checkup`。

在 Codex CLI／IDE 輸入 `/skills` 或 `$`，確認清單中有 `startup-checkup`；若未出現，先檢查路徑，再重新啟動 Codex。路徑與呼叫方式依據 [OpenAI 官方文件](https://learn.chatgpt.com/docs/build-skills)，查核日期為 2026-09-21。

## 第一次使用

在 Codex 貼上以下內容，把方括號換成你的現況。不知道的地方直接寫「未知」，不用先準備完整商業計畫。

```text
$startup-checkup
我在做：[產品或服務，以及想幫助的對象]
目前已發生：[使用、付款、回訪或交付的具體狀況；沒有就寫沒有]
這輪想決定：[一件事，例如先修流程還是加功能]
可投入：[時間、預算或期限；未知可留未知]
不能改動：[已確認的定位、功能、承諾或其他限制]

請先說明檢查範圍，區分事實與假設，選一個主要卡點，提出最小驗證。
這輪只做分析，不修改專案或對外執行。缺資料每輪最多問三題。
```

若要讀取專案資料，指出允許讀取的檔案或資料夾；不要為了診斷而開放整個磁碟或無關帳號。

### 檢查功能優先順序

```text
$startup-checkup
這輪要決定下一個功能先做什麼。請先讀我指定的規格與現況資料，
核對使用者任務、已有能力和實際缺口，再比較替代做法與投入成本。
分清必要修正、待驗證的新功能與暫緩項目；不要直接改程式。
```

### 完整檢查，或帶回結果

完整檢查時可說：「請逐項列出九模組狀態，缺資料標待驗證，最後只選一個主要卡點。」

帶回結果時可說：「這是上次的假設、原判準和這次觀察。請先確認資料能否比較，再更新判斷；不要事後改成功定義。」

## 方法與限制

定向診斷只深入相關的 1–3 個模組；完整檢查才展開全部九個模組。四階段分別關注採用、選擇理由、營運與交接擴展，不預設每個人都要擴大規模。

九模組涵蓋市場適配、客群與場景、需求與付費、定位、功能與信任、收支、交付、決策協作，以及創辦人目標。細節見[檢查框架](references/framework.md)與[證據規則](references/evidence-and-experiments.md)。

- 缺資料代表待驗證，不代表沒市場；朋友好評、註冊、付款與獲利也不能互相替代。
- AI 可能誤讀資料或提出不適合的建議。重要判斷要回到原始紀錄及實際觀察。
- 只讀是指令約束，不是安全沙箱。工具權限由 Codex 等宿主控制；修改、外聯、公開招募、收款與付款都需要另外授權。
- 讀入的資料仍依宿主與模型服務的資料政策處理，不代表全程離線。請先移除客戶姓名、聯絡方式、憑證及無關的商業機密。

## 更新、移除與回報問題

更新前備份你改過的 skill 檔案，閱讀[變更紀錄](CHANGELOG.md)，再決定是否替換。同一環境避免保留多份同名版本。

停用或移除時，確認安裝位置，將該位置的 `startup-checkup` 資料夾移出 skill 目錄即可；保留需要的自訂內容，不要刪除整個 `.agents/skills`。

遇到錯誤可在 [Issues](https://github.com/FarceurLiu/startup-checkup/issues) 提供版本、使用環境、去識別化的提問、預期與實際結果。公開 issue 不要貼客戶資料或完整私密對話。
