# 證據與驗證規則

本檔定義證據與驗證的操作方式；各項門檻需依本輪決策與資料判斷。

## 1. 證據紀錄

每個足以改變判斷的主張，都要有可追溯來源，或明確標示假設。

```text
E01
種類：使用者陳述／已讀原始紀錄／行為紀錄／交易紀錄／公開資料
來源：對話日期、可存取檔案及段落、報表篩選條件，或公開來源與查核日期
資料日期／觀察期間：
對象與範圍：產品、版本、客群、地區、通路、是否付費
實際觀察：只描述看到的事，不先寫成原因
支持：H01 的哪一部分
不能證明：其他未觀察到的部分
限制：招募偏差、樣本、缺漏、是否排除測試帳號、是否受協助或獎勵影響
```

報告以 E 編號連回來源。若宿主支援檔案或網頁引用，在對應判斷附近附上引用。
未能存取來源時記錄「使用者陳述，未獨立核對」。自行生成的例子與模擬資料不得混入證據清單。

資料衝突時先核對期間、分母、客群、事件定義及版本，不直接採最新或數字較好看的那份。
若仍有衝突，並列兩者與影響，保留待驗證。

## 2. 證據支持範圍

- 自述／訪談：支持對問題、理由與期待的理解；不直接證明實際採用或付費。
- 過往行為／替代方案：支持問題曾發生，當事人曾投入資源；不直接證明會轉用新產品。
- 任務完成／真實採用：支持在該條件下能使用並得到某種結果；不直接證明會持續用。
- 付款／採購／續約：支持該價格、條件與期間下的交易；不直接證明市場規模、正常價格需求或獲利。
- 收支／交付／重複交易：可檢查可持續性；必須看完整期間、成本、退款及集中風險。

這些不是總分，也不是把一種資料自動判得比另一種有用。先問本輪究竟要驗證哪個假設。
一筆交易可能比多次按讚更適合驗證付費，但不能代替對流失原因的訪談。

## 3. 必須分開的三條線

**產品可用性**：功能可用、流程通過、任務能完成。
**使用價值**：真實對象在真實情境採用、再使用，或得到可描述的結果。
**商業可持續性**：付費者願意付、收入足以支應交付與獲客、現金時點可承受。

三者分開呈現。不要用「網站已上線」「測試 PASS」「新增了分析功能」推論留存或營收。

免費／平台模式要分清：
- 使用者為何用？何時再用？什麼是有意義的採用？
- 付費者是誰？購買什麼結果？決策者、預算與採購週期是什麼？
- 若有多邊角色，各邊獨立驗證。不得預設平台提供主動媒合、交易或自然流量。
- 尚未啟用收費時，營收待驗證；不能因零營收否定免費使用價值，也不能因免費留存宣稱收費成立。

低頻、一次性購買與長週期 B2B，不適合硬套每日活躍或一週回購。先確認自然需求週期。

## 4. 指標定義

只選一個主指標，必要時加一個避免副作用的觀察項目，例如任務成功率提升但客服工時不能失控。
每個比率都要寫分子、分母、期間、篩選條件及去重方式。

示例定義，不是固定標準：
- 採用率 = 在指定期間完成指定核心任務的合格新使用者 ÷ 同期間取得有效使用機會的合格新使用者。
- 成交率 = 接受指定方案並完成指定付款條件的對象 ÷ 實際收到該方案且符合條件的對象。
- 第 N 期留存 = 同一群初次採用者在第 N 期完成指定再使用行為的人數 ÷ 該群已完整走過 N 期觀察窗的人數。

先定義「合格」「有效機會」「核心任務」與 N 期。不能事後排除失敗者讓數字好看。
分母為零、尚未經過觀察窗或追蹤中斷時，結果是無法計算／待觀察，不是 0% 留存。
不得混用事件次數與去重人數；排除內部、測試、機器流量與重複事件時，說明規則。
質性研究不必硬轉成轉換率；可以用具體任務觀察與可追溯紀錄。

## 5. 最小驗證的設計

順序：一個假設 → 一個可觀察結果 → 最低必要投入 → 原定判讀條件 → 下一步。
優先利用現有材料、人工流程或低成本原型；「原型」是理解需求的工具，不必先完善整個產品。

可用形式：
- 訪談／觀察：重建最近一次情境、當時行動及替代方案。
- 任務測試：讓目標對象用真實材料完成任務，記錄需要協助的位置。
- 真實試用：追蹤取得初次價值與後續自主行為；受陪同操作與自主使用分開。
- 報價／試點：針對付費者，確認條件、決策與實際承諾。只作草案，外聯與收款另需授權。
- 交接演練：用真實但去識別化的案例，檢查別人能否依標準完成，以及何時需要升級。

訪談問題示例：
「最近一次發生是什麼時候？」
「你當時怎麼處理？哪一步最麻煩？」
「最後花了哪些時間或金錢？」
「還考慮了什麼做法？為什麼沒有選？」
避免「你是不是很需要」「有這功能你會買嗎」等先把答案放進問題的形式。

## 6. 門檻與結果分支

確認樣本、期間、成本、成功／反證／不確定條件後，才把測試標記為可執行。
新增數字都標「建議草案」並說明理由。無使用者授權，不執行外部行動。
數字可依既有基準、單次成本、可承擔投入及自然決策週期提出；沒有基礎時，先做探索並收集基準。
小樣本探索是決策線索，不宣稱代表整體市場或具有未計算的統計顯著性。

三種結果：
- 支持：下一步有限增加哪種投入？還有哪個假設沒驗證？
- 反證：修改哪個客群、場景、方案或流程假設？不自動判整個事業失敗。
- 不確定：原因是招募不到、觀察窗未滿、流程故障、樣本不足，還是指標無效？補哪一項資料，而不是無限延長。

停止條件至少包括資源上限與風險條件。重測要有新增資訊或方法修正，不只是期待換到好結果。
不使用假見證、假倒數、假需求、未告知限制的假產品，或未經同意的個資收集。

## 7. 簡化經濟計算

以下是本套件定義的簡化診斷算式。
只在資料具備時算；列出單位、期間及假設，不代替會計、稅務或投資意見。

**單次現金貢獻（自訂口徑）**
= 該次實收淨額 − 隨該次交付增加的現金變動成本。
實收淨額說明是否已扣退款、折扣及代收稅款。變動成本明列材料、運送、計件人力、金流、增量用量等；同一項不要重複扣除。
這不是淨利，仍未扣固定支出與未分攤的獲客成本。

**創辦人工時的經濟負擔**
= 該次實際投入時數 × 使用者確認的估算時薪。
估算時薪是機會成本假設，不是實際現金流出；必須與上面的現金口徑分開，不能重複扣薪資。

**特定期間獲客成本（簡化口徑）**
= 歸屬該期間與通路的獲客支出 ÷ 同口徑新增付費客戶數。
說明是否包含人力及內容成本；長銷售週期有時間落差時，不拿當月支出除當月簽約硬比較。
分母為零時不能算出可解讀的單位成本。免費產品不把新增註冊替代成「付費客戶」。

**現金覆蓋月數（粗估）**
= 可動用的營運現金 ÷ 具代表性期間的平均每月淨現金流出。
只在淨流出大於零、口徑一致、沒有忽略已知大額付款時使用。零或淨流入時不報「無限安全」。
不將個人所有資產視為可動用創業金；不要求使用者交出不必要的帳戶明細。
若支出即將變動，改用已知收付款時點做條件式預估，不用歷史平均冒充未來保證。
